## 性能与兼容性

透传模型开关只是读取账号现有 extra 和映射，不新增逐请求数据库/Redis 查询、worker 或 timer。
Grok 搜索识别为固定前缀判断，仅由已选 xAI 账号启用；其它平台同名 call_id 保持客户端工具语义。
原持久、幂等计费和并发槽位释放路径保持原 owner。

正则修复只读取工具 schema，收集字节位置后一次拼接请求，保留消息、默认值、常量和数值原文。
预检只探测 `pattern` 前缀的小写 ASCII 字母转义（`\u006x` / `\u007x`），中文、Latin-1 与 emoji 提示词不因此被解码；
零分配回归同时覆盖转义 schema 关键字仍能进入修复。
删除不兼容的 patternProperties 键时同时放宽该对象的 additionalProperties，避免误拒绝原本允许的键。
每个 schema 最多 1 MiB、最多 64 层，超大或更深的子树保留原样；每请求超过 4096 次修改则整次正则修复回退原样。
这些兼容规则不作为本站工具执行或授权的参数校验。
相同 Docker/Go/CPU 下的上游方案与本地适配采样见[性能与验证目录](../diagnostics/upstream-sync-20261116-followup/README.md)。

## 平滑升级与回退

本批没有数据库 migration、Ent/Wire 生成结果、持久队列格式或 Redis key 的变化，也不升级工具链。
新旧二进制可以共用原数据库和缓存；新增 JSON 字段为可选字段。
额度读取继续遵循原探测节流和后台推送，不让列表刷新建立新的上游连接；旧节点仍可能把读取时刻误报为观测时刻。

透传模型筛选须在全部网关节点及调度快照写入节点升级后开启；旧节点会忽略该新开关。
启用前写入完整来源模型名单并确认快照已刷新。回退前先关闭筛选开关，或暂停这些账号的调度；
不能依赖旧二进制提供新限制。Carbon 在旧节点中不具备本批新增的目录、思考和兜底价保证，
滚动升级期间应使用明确映射与价格，或待全节点升级后启用新模型。

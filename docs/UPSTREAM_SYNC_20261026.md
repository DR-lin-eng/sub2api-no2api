## 图片计费与升级

管理员分组表单新增 `image_count_billing`，仅在 OpenAI/composite 分组允许生图时可开启。
创建、更新、复制、完整/轻量读取、API Key 主分组与有序绑定快照均传递该字段。
默认 false；旧前端缺失字段仍按原规则运行。迁移使用本项目下一编号
`251_group_image_count_billing.sql`，不覆盖已发布的上游同编号或本地历史迁移；Ent/Wire 从源定义生成。

开关仅改变专用 `/v1/images/*` 端点的结算：实际返回 2 张即按 2 张结算，不按请求 n=7 多扣；
成功响应无法解析张数时，开启按张计费使用 1 张保底，关闭时保留旧 n/流式口径。
优先复用当前分组图片价和按次/图片定价；强制按张时跳过 token 定价分支，避免把缺少 token
输入的图片算成零费用。OpenAI 按次上下文档位补齐实际 token 输入，防止档位未命中。

保留本项目已经解析一次并传递的 `ResolvedPricing`，没有复制上游重复解析和重复构建费用输入的分支。
没有改变账号出口、选号、并发槽位、重试或可靠幂等结算。Responses/Chat/WS 等混合请求仍走原 token
定价；不能仅因响应包含图片就把它标成专用图片端点，否则可能漏计文本费用。

鉴权快照版本从本项目 25 增至 26，保留此前的蒸馏策略和有序分组字段。滚动期间先保持开关关闭，
等全部节点升级后再开启，避免旧节点忽略新开关而产生不同结算。回退前关闭该开关可恢复统一旧口径。
旧二进制可读取已添加列的数据库，并在更新其他分组字段时保留未知列；不执行破坏性 Down SQL。

## 管理员密钥与性能审查

现有认证已经提供多枚摘要密钥、scope、到期与撤销、一次性显示及 JWT-only 生命周期，不重复造第二套密钥。
本轮独立移植限流语义：每枚 Key 使用独立全局/重查询桶，仍通过一次 Redis `AllowMany`；管理员 JWT
保留现有豁免。机器密钥认证仍执行原 scope、审计与权限规则，不改变已有 Key 的资源授权范围。

上游 `ScopedAdminList` 在分页后逐账号调用 `loadAccountGroupIDs`，会随页大小增加数据库往返。
资源级账户写入还要求事务内重新验权、提交后发布缓存，而本项目另外有账号出口、Spark、批量操作、
权限组和扩展模块。直接覆盖上游旧目录及权限目录会遗漏这些入口，并引入与当前 JSON 密钥存储并行的
另一套数据库事实源。因此资源级授权保留明确专项：版本化 scope/policy 迁移、跨版本密钥写入协议、
全部扩展写入口的事务复核、分组批量加载、SQL 次数预算、大账号/代理池基准和响应字段白名单。
不得将暂缓功能当成已经覆盖，也不重复审查已关闭的生命周期与限流子项。

图片正常计费分支仅新增布尔判定，不增加数据库查询、外部目录访问、队列或 goroutine。
固定 Docker 微基准的逐次数据与中位数见诊断目录 `PERFORMANCE.json`，只代表函数夹具，不能外推生产吞吐。

# 上游 PR #8170：Grok 4.7 Fast 价格修复

从本项目主线 `66ee90b06e3dc920d683f189fdff9abbacfcaae8` 继续，冻结范围只包含上游 [#8170](https://github.com/Wei-Shaw/sub2api/pull/8170)，merge SHA 为 `dba770d56a0ee0ae5bad1b3dc5e11614d323163c`。之前的关闭账本保持原样；本项的关闭与重开条件见 [机器台账](../diagnostics/upstream-sync-20261022-pr8170/UPSTREAM_PRS.json)。

## 价格与实现

按 [xAI 官方价格页](https://docs.x.ai/developers/pricing) 的 Fast 价卡，每百万 token 的 USD 价格为：

| 提示词长度 | 输入 | 缓存读取 | 输出 |
| --- | --- | --- | --- |
| 小于 200k | 4 | 1 | 12 |
| 达到 200k | 6 | 1.5 | 18 |

边界沿用上游 #8170 与项目现有 xAI 的 `>= 200000` 口径。官方 Fast 文本使用 “above/exceeds”，而标准 xAI 表格写作 `>=`；这次没有改变既有边界约定，测试明确覆盖 199999、200000、200001。

`billing_grok_fast.go` 负责两个明确 ID：`grok-4.7-fast`、`grok-4.7-build-fast`，并复用现有 xAI 前缀清理。内置兜底和捆绑快照均有独立 Fast 价格，计费准入可确定识别这些 ID。本项目解析器使用显式长上下文阈值/倍率字段，快照同时带上这些字段，避免仅复制上游 `above_200k_tokens` 字段后仍无法启用长上下文档。动态价格转换也保留 Fast 的等于边界语义。

自定义 feed 和渠道的明确价格继续优先。普通 Grok、未来未知型号、模型映射、账号选择及 reasoning 参数保持现有行为；没有数据库迁移，不重算历史用量。Fast 在官方文档中只供 Cursor/Grok Build 使用，本改动只修正已被现有账号显式路由的 Fast 用量价格。

## 验证

Docker 使用固定短上下文夹具（100000 新输入、50000 缓存、10000 输出）与 200k 提示词夹具（150000 新输入、50000 缓存、10000 输出）。本地原有未知 Grok 兜底缓存价为每百万 0.30，因此基线分别为 `$0.275` 和 `$0.750`；修复后分别为 `$0.570` 和 `$1.155`，普通 Grok 4.6 对照保持原金额。

测试包括两个 Fast ID、大小写/前缀、捆绑文件解析、199999/200000/200001 边界、倍率、自定义 feed 和渠道价格优先级。真实 Docker HTTP 流式与非流式请求通过同一数据库升级/回退，检查用量记录和费用落库。完整结果见 [诊断材料](../diagnostics/upstream-sync-20261022-pr8170/)。

固定 Docker 微基准中，Fast 计价耗时约下降 48.7%，分配从 5 次降至 4 次；普通 Grok 4.6 耗时约增加 4.7%，分配保持 5 次。数据只代表计价函数夹具，不代表网关吞吐。

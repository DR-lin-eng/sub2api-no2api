## 当前 owner 的适配

邮箱黑名单缺省为空，不会自动禁用历史账号。保存后先展示匹配名单，管理员确认后才调用批量禁用；
管理员和已禁用用户被跳过，失败时前端保留未提交的批次。编辑名单和确认名单均最多渲染 200 行，
确认人数与实际处理仍覆盖全部匹配用户，避免 20,000 用户时创建同等数量的 DOM。状态更新及 MCP 授权撤销同事务完成，再走现有
API Key 鉴权缓存失效路径。没有启动自动清退任务，也没有操作生产用户。

沿用本项目 `NormalizeEmailForAliasDedup`：仅 Gmail 家族折叠点号、加号后缀和 googlemail 域名，其他域名
保留点号与加号。SQL 探针保留同一规则，并由 application 复核，避免错误命中自定义邮箱。名单缓存的刷新与
保存串行，防止旧查询覆盖新保存；跨实例最多等待 60 秒。首次读取失败且无旧快照时沿用不拦截策略。

解析快照只保存独立标量、协议、偏移和进程内指纹，不保存旧 body；每次尝试有独立 Ref，Replace 使快照失效。
同一存储的原地变化也会通过指纹退回解析。初次解析增加一次指纹计算，复用阶段省去 JSON 验证和字段重扫。
thinking 预检遵守解码器的重复键后值优先语义；需要修改时仍走原解码器。
Read 工具参数在容器/字符串尚无末尾闭合符时跳过完整 JSON 校验；可能闭合的片段仍由原校验器判定，
标量保持原路径。字符串内部括号、外部替换、复制状态和完成后迟到分片都有回归覆盖。

保留当前 sjson 大请求批量编辑器，不引入 moego alpha 依赖。上游 orphan 完整 map 清理阶段不存在于当前
owner，继续使用本项目 continuation sanitizer；Codex bootstrap 已有共享预检，不重复实现。现有
Anthropic/Chat/Responses builder 和 Responses→Chat 进度记录也继续复用。

隐私要求是请求所属分组的候选条件，覆盖普通、粘性和 previous_response 选择，不把共享账号永久标错。
组 ID 不匹配时不借用认证组；有序分组切换继续读取实际分组。RPM 缓存区分“该分组确认无覆盖”和“未知/失败”，
未知或换组时继续回源，显式 0 仍为不限流。没有删除并发槽位、失败排除、利润准入或释放路径。

通知队列只承载尽力发送的提醒，4 个 worker、128 个排队任务，单任务 30 秒；拥塞有计数和限频日志。
结算和配额持久化不进入该队列。本项目原有 PostgreSQL 幂等账务与持久平台配额保持原 owner，旧非 flusher
镜像写入在 usage worker 内用独立 5 秒 deadline 执行，失败继续记录计数。同步溢出模式仍可能让调用者承担
数据库背压，worker 数量不是全局数据库并发上限。

摘要会话存储使用 16,384 条/32 MiB 的 LRU 与主动 TTL 清理，压力淘汰后正常回到选号流程。已重构的 OpenAI
兼容会话缓存保留原 10,000 条 owner 与行为，没有另造一套状态源。Wire 源图修改后重新生成生命周期装配。

## 平滑升级与回退

本轮没有新增 SQL migration、Ent schema 或运行依赖。鉴权快照升级为 v27，继续携带本项目 v26 的图片按张
计费和更早的策略字段；旧格式走缓存 miss 和完整回源。混合版本可能反复回填不同版本、增加临时回源开销，
应完成全节点升级。回退保留数据库，不执行 Down SQL。

黑名单必须在所有注册、发码、绑定节点及前端升级后启用；旧节点不认识该设置。回退前清空名单，或暂停
注册/绑定入口，不依赖旧节点实施新策略。已确认禁用的用户状态是持久管理操作，二进制回退不会恢复用户。
退出传输故障冷却需要显式配置并重启节点；开关不会清除已经存在的冷却和管理员暂停。

边界修复会明确拒绝超限输入：解压输出超过既有 64 MiB 上限返回错误，zstd 使用单 decoder、8 MiB window；
损坏 trailer 不再当作截断成功。Gemini 单行遵守本项目当前 40 MiB 默认及显式 `max_line_size`，Bedrock 在
分配前检查 128 KiB headers/16 MiB payload，Antigravity 非流式响应复用现有配置读取上限。

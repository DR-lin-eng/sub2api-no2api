# 代码审查与范围关闭

审查依据为冻结的 33 个 PR 原始 merge diff、当前模块 owner 和上一轮关闭台账；原始摘要由
`verify_ledger.py` 独立验证。不是将上游源码目录整体合入。

## 关键边界

- 刷新令牌：检查在消费之前，Redis 消费不可用时不签发，没有非原子 fallback。新增端口由所有实现与
  测试 double 显式实现；缓存 JSON/TTL/绑定和令牌家族仍由现有 owner 管理。并发在服务、Redis 脚本和真实 HTTP 层验证。
- 调度：容量 shed 默认保持请求级保护，只有显式 model scope 进入当前规则 owner，实际模型映射只做一次。
  output/metadata 中的关键词不参与匹配，失败不升级为整号惩罚；槽位释放已覆盖，不重复改写。
  later-turn WS 错误不允许 handler 用首帧回放；已输出的错误不重放请求。
- 协议：page context 仅匹配严格形状、无真实 call_id 的 agent 输出，仍作为不可信 user 文本；
  重复键/非法 JSON/真实工具结果不被宽松修复。UTF-8 检查在规范化和准入之前。
  encrypted function args 保留原 JSON；reasoning envelope 不作为真实 provider ciphertext 重放。
- 支付与账务：成功码是每实例显式选择，缺省 1，订单查询仍按原成功码处理；小数码不经整数截断变成成功。
  六位倍率与币种结算精度独立，过细正数不得保存为零，大有限值不能在缩放时变成 Inf。
  现有可靠队列、订单快照、金额和幂等结算保持在原 owner，没有丢弃/采样路径。
- 审计：持久发布成功才发通知，通知不承担可靠性；每次只唤醒一个配置中的 worker，有界合并。
  队列 fencing、续租、恢复和关停仍由当前模块处理，真实存储测试另库运行。
- 前端：请求统一经过既有 datasource/client，未增加浏览器权限事实源或令牌持久化；额度纯转换静态导入，
  不迁移请求、timer 或生命周期。表格刷新仅控制 busy/inert，保留行和已知值。退款码双语提示、手机表单和模型目录已验收。
- 升级：只有兼容旧二进制的并发覆盖索引，没有重编号旧 migration 或修改生成文件。索引构建失败恢复走现有 runner。
  旧节点保存倍率/执行成功码 0 退款等混合版本风险在升级说明中显式限制，不宣称所有新行为在混合版本期间一致。

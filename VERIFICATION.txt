Implemented behavior:
- The gateway resilience setting is independent from the 429 policy and defaults disabled.
- GET/PUT /api/v1/admin/settings/oauth-401-cleanup reads and writes {"enabled":true|false}.
- When enabled, an upstream model-gateway HTTP 401 can soft-delete only a direct type=oauth credential owner.
- API Key, Setup Token, and credential-shadow accounts never enter the delete repository path.
- Full credentials JSONB equality, including _token_version, is checked under a PostgreSQL row lock.
- A credential CAS miss preserves a concurrently reauthorized account, fails over only the stale request, and does not install an account-level runtime block.
- A successful delete includes linked shadows, group and egress bindings, scheduled tests, scheduler outbox events, cache cleanup, and a short deletion block against concurrent stale snapshots.
- A repository failure falls back to the pre-existing 401 cooldown/error path.
